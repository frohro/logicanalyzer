# Prompt for Adding the Pico2Pico Logic Analyzer to Dr. Gusman's Analyzer
I do development on the Raspberry Pi Pico and Pico2 and their wireless versions.  I would like to use a logic analyzer occasionally in that work.  I want to be able to sample without aliasing at the clock speed of the pico I am using as the device under test (DUT), so I make this analyzer work in "state mode," where the clock of the DUT clocks the logic analyzer capture as well.  The folder pico2pico_test contains a proof of concept project where I stacked two picos on top of each other and used the clock of the master (DUT) to clock the slave (logic analyzer).  This project was simple.  Now I want te use the principles developed there to make a new board for Dr. Gusman's LogicAnalyzer.  The idea behind doing this is that I can plug in the two pico stack into a PCB that uses a pico, and program the master as the PCB requires to exercise the board, and add only one line in C to send the clock to the master, which will capture the logic analyzer data without aliasing at the clock speed of the DUT.  This provides two very important and useful features:
- Since the picos are so close and all GPIOs (except GPIO20/21) are wired together there are no cables to connect from the DUT to the logic analyzer.  Connecting those cables is a real pain.  Those cables are usually not short, so they cause delays, reflections, etc. that can make the circuit behave differently with the analyzer hooked up than without. There is a jumper between GPIO21 (GPOUT0) of the master (DUT) to GPIO20 (GPIN0) of the slave.  I plan to solder a jumper from GPIO20 of the master to GPIO21 of the slave (logic analyzer) so GPIO20 of the master can be monitored by the analyzer.  Other GPIOs go from one pico to the other match.
- Since we are using the DUT's clock, there will be no aliasing at any frequency we can clock the DUT pico, making this as fast as a logic analyzer in the time mode running at four or five times the speed.
## Firmware Modifications
We need to add our board te the LogicAnalyzer_Board_Settings.h.  We also need to modify the code so it will accept the clock input from the master and switch back and forth on capture commands.  Let's call this unit PICO2PICO.  Eventually we might make a board PICO2TOPICO2, for the Raspberry Pi Pico2, but for now let's make this work for the Pico RP2040 device.  We want to normally (especially for USB communication) use the slave's own 12 MHz clock from its crystal, but for captures, use wish to use the system clock from the master coming in GPIO20 of the slave.  All the GPIO of the slave (logic analyzer) will be inputs.

We need to think about how to implement the "state mode" in this analyzer, since to this point, Dr. Gusman's analyzer has only been using "Time mode", where the logic analyzer uses its own clock.  To start with I think we need to assume the clock of the logic analyzer is running at the same speed as the clock of the DUT, so the GUI display does not have to be changed.  Perhaps, in the future, we can remove that assumption, and consider if it might be less data to send if we only send the number of clock ticks a transition occurred at instead of the data value at each clock tick (assuming the LogicAnalyzer works this way).

I want to put this all in the pico2pico branch of the git repository on GitHub.
